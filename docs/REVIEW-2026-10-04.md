## Fixes (each with tests)

- **The tokenizer splits on the whole `%s` class, not just space and
  tab** (`parser.lua`). The bare-word branch finds its end with
  `find("%s")`, but the separator check only stepped over `" "` and
  `"\t"` — a `\v` or `\f` inside a bare word landed `word_end` ON the
  cursor: an empty token, a cursor that never advanced, and a
  "table overflow" error instead of a command (probed: one keystroke
  into the buffer). redis-cli's `sdssplitargs` splits on `isspace()`,
  so the full class separates bare words and a key carrying one is
  written quoted, like a key with a space; a comment starter after a
  `\v` is still at a word boundary.
- **A display-capped cell refuses writes that would store its prefix**
  (`grid_edit.lua` + value viewer). A list element or hash value past
  `--max-bytes` renders as its first N bytes, and both sides of the
  verified list write are capped by the same limit — probe and cell
  compared EQUAL, so `LSET`/`HSET` stored the prefix as the WHOLE value
  and the tail was cut with no trace (the worst class this codebase
  guards against: a silent wrong-value write that answers OK). The
  executor now flags those rows per item (`item_truncated` /
  `value_truncated`, see the sibling poste.nvim round); `edit_cell`
  refuses such list/hash/set rows, `delete_row` refuses a capped SET row
  (its `SREM` consumes the cell text and would match nothing), while
  list `dd` stays allowed (index-addressed; it deletes the whole element
  on purpose) and hash/zset `dd` delete by a never-capped name. The
  value viewer shifts a list page's flags array with the row index, so
  the lookup by true list position stays aligned from page 2 on — an
  unshifted array made the guard miss every capped cell past page 1.
- **A RESP3 `map` tab edits as the hash it is** (`grid_edit.lua`).
  `value.type "map"` is the RESP3 spelling of a hash and the grid
  builders already render it as one, but the editors matched only
  "hash": `i`/`dd` refused it as an unsupported type, and `add_row`'s
  verb fallback fell through to `SET key <v> KEEPTTL` — replacing the
  whole collection with a string. Normalized in `key_context`, where
  every editor reads its type. Today's binary answers `Map` replies with
  type `"hash"` (probed in redis_executor.rs), so this is
  defense-in-depth against the shape rather than a live path — which is
  exactly why the renderer accepts both spellings and the editor must
  too.

## Probed, held (recorded on purpose)

- **`add_row` refuses an empty-string value silently.** `SET key ""` is
  a legal Redis write, but an empty prompt answer is far more often a
  cancelled prompt than a deliberate empty value; the silent return
  reads as "cancelled". Held.
- **`list_connections_sync` returns `db` as a string when derived from
  the URL** (`/0` capture) and as a number from the `db =` field. Both
  flow into display today; a consumer doing arithmetic would trip. Held
  until one exists.
- **`util.truncate_display` with `max_width <= 0` returns `"…"`** (one
  cell wider than the cap). No caller passes a non-positive width; held.
- **`util.redact_url` keeps a colon-less userinfo** (`redis://user@h`
  renders `://user@h`). The password is the secret; a bare username is
  not. Held.
- **CI's test step swallows failures** (`./tests/run.sh || echo
  "::warning::"`, poste-db does the same). A missing binary in the CI
  image is the documented reason; the lint job stays strict. Held —
  making it strict needs a CI run with the binary present to know the
  suite is green there.
