## Bugs fixed

1. **`runner.lua`/`exec_run.lua` — multi-USE files pinned results to the
   first group's lines** (b6c3201). redis-exec restarts `seq` at 1 per batch,
   and `present()` mapped `batch_lines[ev.seq]` where `batch_lines` is the
   whole FILE's statement list. Group 2+'s success/error signs landed on
   group 1's lines (or silently dropped past its length). `dispatch_group`
   now stamps each result with `ev.src_line` from its parser entry (results ↔
   entries are 1:1 per batch — greedy, failed commands still emit), and
   `present()` prefers `src_line`, then `start_line`, then the single-batch
   seq mapping.

2. **`connections.lua` — the sticky `false` sentinel served a stale
   not-found forever** (dc4aed7). A connections.toml created while nvim was
   open was invisible to resolve/listing/completion/browser until restart —
   the exact bug the poste-es twin fixed yesterday (ffdbe52). Negative
   walk-ups now re-probe every call; positives keep the mtime cache;
   `invalidate()` stays as the pickers' re-probe hook (both pickers call it).

## Refactors

- **`exec_run.lua` — consecutive error groups advance in a loop** (915db4e).
  `dispatch_group` recursed once per error group (failed/bare USE); a file of
  10k broken USEs nested 10k frames before the first real batch. Real batches
  already re-enter on a fresh stack via async on_done. Pinned by a
  3000-group depth probe.

## Verified clean

- **Session db steering has no cross-SELECT race**: an execute's SELECT and
  its command are two consecutive `chansend` writes inside one synchronous
  call, and the session processes stdin FIFO — interleaving executes from
  other features can only insert whole SELECT+command pairs, never between a
  pair. The failed-SELECT path correctly fails the pipelined command (09-06
  fix re-verified).
- Credentials: `redact_url`/`redact_cmd`/`host_label` all strip userinfo;
  history keeps commands/results in memory only; browser winbars show
  credential-free hosts (grid-edit spec pins this).
