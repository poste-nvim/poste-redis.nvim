## Bugs fixed

1. **`runner.lua` — `:PosteRedisRunFile` ignored the selected context for
   pre-USE commands** (c3eaee6). The "No connection for line N" error told
   users to run `:PosteRedisConnection`, but the retry still passed no
   default URL into `run_file_async` — the selection never reached
   `group_by_connection`, so a USE-less file could NEVER run against the
   picked connection. `run_file` now passes `redis_state.current_url` as the
   run-level default; USE groups keep winning via dispatch_group's force
   extend (the mechanism the 09-x rounds already built for this exact shape).

2. **`exec_run.lua` — a failed jobstart was silent AND stranded the dispatch
   chain** (0bf3681). The start-failure branch bumped `exec_seq` BEFORE firing
   the guarded `on_error`, and `guarded()` drops callbacks from a superseded
   seq — "Failed to start redis-exec" never reached anyone, `on_done` never
   fired, so single runs left their "running" spinners forever and multi-USE
   chains stranded on the failed group (red line #4). Order is now: guarded
   on_error (seq still current) → invalidate the seq → unguarded pcall'd
   on_done, which only unwinds the caller; any run the dispatch chain starts
   from there takes its own newer seq.

3. **`browser/value.lua` — list viewer pages numbered rows by page position,
   not list position** (55c098c). Every LRANGE page restarted the grid's index
   column at 1, but `grid_edit` derives the LSET/LINDEX index from that cell:
   editing/deleting a row on page 2 verified the WRONG element — the
   verified-write refused with a bogus "List changed since render" warning,
   and when the element at the page-local position happened to hold the same
   value, the write corrupted a different row entirely. Page fetches now
   capture the cursor base and re-stamp `rows[i][1] = base + i`; the index
   column doubles as the true list position (display: page 2 reads 501…,
   matching the "loaded 1000" footer; edit/delete: correct index).

## Verified, not changed

- **Credential exposure in the panel/history label chain is closed.**
  `runner.present` falls back to a raw URL when no connection NAME resolves,
  but `current_url` and `context.connection` are only ever written together
  (`connections.apply_connection`), the winbar renders through
  `util.host_label` (userinfo stripped) and history is in-memory only. A
  future writer that sets `current_url` without a name would leak through —
  worth a hardening pass if one ever appears.
- `session_conn.lua` — the flush-deferred render machinery stays: in_flight
  only reaches 0 between pages for a timer tick, so paced renders land at
  scan end; deliberate (nvim 0.12 channel-starvation fix, see async.lua).
- `statusline.lua:185` `ctx ~= "" and M.get_context_hl() or nil` — safe:
  the fallback is nil, so a nil/false middle degrades to the same value.
- `parser.lua` single-quoted tokens keep backslashes literally
  (`'a\'b'` → `a\'b`); redis-cli uses `'\''` instead. Documented family
  convention, not touched.
- `context.lua` entry cache cleans up on BufDelete only; a wiped-but-not-
  deleted buffer leaks one cache entry, and bufnr reuse almost surely bumps
  changedtick → re-parse. Negligible.
