## Bugs fixed

1. **`toml.lua` — the vendored copy predated poste-db's single-pass
   unescape fix** (f743dc1). The c3f2de5-era copy still decoded basic
   strings with sequential gsubs, so an escaped backslash re-formed an
   escape in the decoder's own output: `password = "a\\nb"` parsed as
   `a`+LF+`b`, `"D:\\tables"` as `D:`+TAB+`ables`. The vendor header says
   to re-copy when poste-db updates — poste-db fixed this in b7aefc6; the
   copy now matches that commit and a one-pass regression test pins it.

2. **`connections.lua` — the URL-derived list host captured userinfo
   whole** (e5ccfba). `list_connections_sync` derived `host` from the raw
   URL with `"^rediss?://([^/@]+)@"`, so a `redis://user:pass@host` URL
   with no explicit host field put `user:pass` in the entry's host field.
   Nothing renders host today (the browser reads name/url only), but it
   is a credentials surface waiting for a consumer; the userinfo is now
   stripped before the capture and the bare-host semantics are unchanged.

3. **`health.lua` — the redis-exec probe didn't quote the binary path**
   (e5e59b4). `systemlist(binary .. " --help")` broke on an install path
   with spaces while the `--version` probe above it already quoted —
   health would report redis-exec missing instead of probing. Now
   `shellescape`d like its sibling.

## Decision implemented (deferred from 09-09)

- **The value-viewer footer no longer rides `tab.lines` for text tabs**
  (7405f29). The 09-09 round noted `yank current` on a string key copied
  the `(loaded N / total M …)` footer with the value and left the
  asymmetry as a decision; this round made it: `add_page` carries the
  footer in `meta.footer` for BOTH kinds and the text render appends it
  at display time. `tab.lines` is now the pure value for yank/K; the
  panel still shows the footer. Pinned by a spec asserting the yank is
  footer-free while the buffer renders it.

## Feature

- **USE completion follows connections.toml changes** (bee1d04).
  `ensure_conn_names` cached the names for the whole session and nothing
  ever called `clear_conn_names` — a connections.toml written or edited
  mid-session stayed invisible to completion even though the pickers
  re-probe via `invalidate()`. The cache now invalidates off a
  config-path + mtime fingerprint. The connection-names spec also stops
  chdir'ing the suite into the temp dir it deletes (the mail 09-08
  cwd-poisoning lesson — it leaked the chdir into every later spec file).
