## Bugs fixed

1. **`SET` edits silently cleared the key's TTL** (`browser/grid_edit.lua`)
   — a bare `SET key value` drops the expiry in redis, so editing a
   string's value through the grid (`i`), or overwriting it via `o`,
   un-expired the key as a side effect of an edit. Both write sites append
   `KEEPTTL` now — a no-op on keys without a TTL, requires redis >= 6
   (playground and CI run redis:7). Command shapes pinned by two specs.

2. **Export refused `~` paths that completion itself suggests**
   (`buffer/export.lua`) — `vim.fn.writefile` does not expand `~`, so a
   typed `~/exports/x.csv` (which `completion = "file"` offers as a
   target) failed with a no-such-directory error. The picked path is
   expanded before the write, pinned by a spec that stubs the pickers and
   writer and asserts the expanded path reaches `writefile`.

## Recorded, not changed (with rationale)

- **`parser.tokenize_line` treats `--` as a comment only at a token
  start** — `GET a--b` keeps the whole token (keys may legitimately
  contain `--`), so `GET a-- comment` reads the key as `a--`. redis-cli
  would treat any `--` as a comment start; the parser's word-boundary
  rule is the better trade for real key names and is documented as such
  on the tokenizer.
- **`verified_list_write` compares the rendered cell against LINDEX's
  reply** — a display-transformed cell (binary preview, long-value
  truncation) can never equal the stored value, so editing such list
  elements is refused with the refresh hint. Fail-closed by design: the
  check exists to block stale-index writes, and refusing a legitimate
  edit costs one `r` refresh.
- **`export.to_csv` does not pad short rows** — grid rows are built
  uniformly by `result/grid`, so a short row would misalign columns; no
  current producer creates one.
