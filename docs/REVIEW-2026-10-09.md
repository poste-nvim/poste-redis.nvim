## Bugs fixed

1. **A fractional score displayed in `%g` but yanked in full precision**
   (`format.lua`, commit `3b05fb5`). `cell()` rendered non-integral numbers
   with `%g` — six significant digits — while `util.to_clipboard` spells
   the same number with `tostring`'s fourteen: a zset score of `1234567.5`
   showed as `1.23457e+06` in the grid and copied as `1234567.5`. Display
   now reads through `tostring`, so the cell shows what the clipboard
   gets.

2. **A hex-spelled port string resolved through LuaJIT's hex tonumber**
   (`connections.lua`, commit `a1f4d6a`). The `field()` helper read its
   value with plain `tonumber`, and LuaJIT's accepts `"0x10"` (even with
   base 10): a quoted `port = "0x10"` typo built `redis://h:16/0` — the
   wrong server, no error anywhere. Same decimal-grammar gate the SQL
   mirror adopted the same day (poste-db `868bdef`), so one shared
   connections.toml now reads identically on all three resolvers.

## Probed, held (recorded on purpose)

- `parser.tokenize_line` on an unterminated quoted token whose last char
  is an escaped quote (`GET "a\"`): the token is kept verbatim and
  `unquote` decodes the trailing backslash literally — the server sees
  key `a\`, where redis-cli would wait for a continuation line the file
  format does not have. The quote-your-key escape hatch (`GET "a\\"`)
  works. Held.
- `SET k c:\\` at end of line reads as a line CONTINUATION (the trailing
  backslash), so the value merges with the next line — the same
  ambiguity every `\`-continuation syntax has (Makefiles). Quoting the
  value keeps the backslash. Held.
- `util.render_command` quotes on `%c` (C-locale controls: 0x00–0x1F,
  0x7F) while the Rust `display_token` quotes on Unicode Cc (which adds
  U+0080–U+009F): a token carrying a C1 control renders unquoted in the
  Lua history line and `\xHH`-escaped in the Rust echo. The contract is
  one-directional (Lua re-parses the Rust echo, never the reverse), so
  the asymmetry is benign. Held.
- The danger blacklist answers on decoded heads only — `is_dangerous_-
  command('"FLUSHALL"')` is false by design, because every caller passes
  `head_of(...)` output (re-probed this round).
