## Bugs fixed

1. **A quoted header behind whitespace kept its quote characters**
   (`toml.lua`). The fast quote check on a `[section]` header inspects
   only the character right after `[`, so `[ 'local' ]` — legal TOML —
   took the unquoted path and stored the section under `'local'`, quotes
   included; `resolve` never found it under `local` and the connection
   silently vanished from every list. The unquoted path now strips a
   MATCHING quote pair (with `unescape_basic` for the double-quote
   form); a name whose ends merely look like quotes (`[a"]`) stays
   verbatim. Pinned by 2 tests in `toml_spec`. The same fix landed in
   poste-db (the vendored copy's source) and a tail-diff confirms the
   two bodies stay byte-identical.

2. **Numeric underscores degraded the value to a string** (`toml.lua`,
   same commit). `port = 64_000` is a legal integer; plain `tonumber`
   rejected the `_` and the value became the STRING `"64_000"`, failing
   far from the typo with "expected an integer". The retry strips
   underscores and is guarded to fully-alphanumeric tokens, so `_10` and
   `foo_bar` stay strings. Pinned by 2 tests in `toml_spec`.

3. **A password carrying an `@` leaked through `redact_url`**
   (`util.lua`). The userinfo is everything before the LAST `@` of the
   authority, but the scan stopped at the first:
   `redis://u:p@w@host` printed `p@w` verbatim as if it were a plain
   username. The same first-match shape redacted the HOST away when an
   `@` sat in the path. The redaction now splits the authority at the
   first `/` and takes the last `@` inside it; a colon-less userinfo
   (an ACL username) stays visible, as before. Pinned by 3 new tests in
   `util_spec`.

4. **A host carrying its own port built a doubly-coloned URL**
   (`connections.lua`). `host = "localhost:6379"` — the
   connection-string habit — produced `redis://localhost:6379:6379/0`,
   which only failed at the binary with a URL parse error naming
   nothing. Both are now rejected at the Lua side with a message that
   says what to change (the port-in-host case names the host; the
   whitespace case says "whitespace is not allowed"). Pure hex+colons
   still pass — that is an IPv6 literal for `url_host` to bracket.
   Pinned by 2 tests in `connections_spec` (44 → 46).

## Probed, held (recorded on purpose)

- `parser.extract_entries` held every shape thrown at it: BOM, CRLF,
  lone CR, NUL inside a key, an unclosed quote (token keeps its quote),
  `\` at EOF, an empty continuation line inside a word split, a 100 KB
  bare token, mid-word `#`/`--` (comment checks stay at word boundaries),
  quoted `USE`, bare `USE`.
- `unquote` round-trips `\xff` to a raw byte, keeps `\xzz` verbatim,
  handles a trailing backslash, empty quotes, a lone quote, and `\'`.
- `render_command`/`escape_for_line` are type-total (numbers, booleans,
  nil, control bytes) and never leak a gsub count.
- `to_clipboard` stays finite for NaN/inf (text), huge doubles
  (scientific), and a self-referential table (vim.inspect's cycle form).
- `substitute_vars` converges on nested refs, caps cycles at depth 10
  (`{{A}}` survives a cycle untouched), keeps unknown refs literal, and
  matches the CLI's `{{…}}`-with-anything shape.
- `build_url_from_fields` rejects port 0/65536/floats/booleans and
  non-string hosts with the connection named; an IPv6 host is bracketed;
  a UTF-8 password is percent-encoded.
- `format_result` on a nil event, a batch error, a huge/NaN integer, a
  hash with no `entries`, a negative `len` — all render or fail closed;
  `preview_json` survives a self-referential table via the pcall.
