## Bugs fixed (file:line at fix time, root cause)

1. **`parser.lua:76` — double-quote escapes decoded by sequential gsub.**
   `unquote` ran `\"` → `"`, then `\\` → `\`, then `\n`/`\t`/`\r` passes, so
   the JSON sequence `\\n` (backslash + n) collapsed to `\` and re-matched as
   `\n` — decoding to a newline. `SET k "a\\nb"` executed with a literal LF
   inside the value. Fixed with a single-pass `gsub("\\(.)")` decoder; unknown
   escapes stay verbatim. (b850e64)

2. **`exec_run.lua:359` — USE groups ran on the default connection.**
   `dispatch_group` merged options with `vim.tbl_extend("keep", opts,
   { connection = g.connection })`; "keep" gives `opts` precedence, so with a
   run-level default URL every USE group's batch was dispatched against the
   default instead of its resolved URL — a multi-USE file silently executed
   whole sections on the wrong redis. `"force"` gives the group connection
   precedence (group_by_connection always sets it outside error groups, so
   the default still applies exactly to commands before any USE). (55fbca7)

3. **`session_conn.lua:236` — failed SELECT stranded the session on the old db.**
   The db auto-SELECT was fire-and-forget (constant `seq 0`, no pending
   entry) while `session.db` was already updated: a failed SELECT (e.g. db
   index out of range) left the connection on the previous db and every later
   request ran there — silent wrong-db reads AND grid-edit writes — while the
   UI claimed `opts.db`. The SELECT now gets its own seq + pending entry; on
   failure it reverts `session.db` and fails the command pipelined behind it
   (whose reply raced in from the wrong db). Seqs are allocated SELECT-first
   so the two requests never collide. (a9f7aa2)

4. **`buffer/sort.lua:135` — sort-icon highlight landed on padding.**
   `icon_range` assumed the icon is the last `#icon` bytes before the cell's
   trailing space, which only holds when the column has zero right-padding.
   Any data cell wider than the decorated header (the common case) leaves pad
   between icon and separator; the highlight colored the padding and the icon
   stayed uncolored. The icon is now located by plain byte find inside the
   column's separator-delimited region. (97109be)

5. **`browser/value.lua` — streams never paged; stale fetches polluted a new
   view.** Two fixes in one commit: (a) the stream type had no branch in the
   page handler, so the first XRANGE page was marked `done` and the footer's
   `<Tab> next page` hint had nothing behind it — streams now advance via the
   exclusive last id (Redis 6.2 `(` prefix) and stop on a short/empty page
   (`browser/value.lua:170`); (b) `add_page` bound to the current global
   `view`, so a slow fetch for a previously opened key appended its page
   (labeled with the NEW key) into the new view's tab list — pages now bind
   to the owning view and drop when superseded (`browser/value.lua:102`).
   (b4f0c6f)

6. **`browser/scan.lua:576` (and siblings) — key-derived prefixes not
   glob-escaped in SCAN MATCH.** Folder prefixes and delete targets are
   literal key names but were concatenated into `MATCH` raw: expanding or
   deleting a group named `a*b` issued `MATCH a*b:*` and swept up `aXb:*` —
   wrong children under the folder, and a batch delete that killed keys
   outside the prefix. Added `util.glob_escape` (`util.lua:119`) and applied
   it at every key-derived MATCH site: group expand (`browser/scan.lua:576`),
   prefix/node/multi-select deletes (`browser/actions.lua:210,284,391`),
   group info scan (`browser/info.lua:94`), the executable `scan_pipeline`
   yank (`browser/actions.lua:44`), and the search query
   (`browser/async.lua:290`), which previously kept its own private copy of
   the escape (DRY'd). (8cdd271)

## Bugs found but not fixed (rationale)

- **`context.lua` incremental parse splits a continuation across the cache
  boundary** (`buffer_entries_cached` extension path): an entry whose `\`
  continuation spans `parsed_upto` parses as two fragments. Harmless for
  context resolution only as long as the split fragment is never USE/SELECT
  (documented in-code); a pathological `SELECT \` continuation would be
  missed on one keystroke. Fixing requires re-parsing a window before the
  boundary — left alone deliberately (comment already flags the boundary).
- **`result/header.lua` stale type/sort extmarks on non-zero leftcol** —
  when the viewport is scrolled the namespaces are not cleared, but
  `nvim_buf_set_lines` collapses the previous extmarks to empty ranges, so
  nothing stale renders. No user-visible effect found.
- **`history.lua` / `grid_edit.lua` / `browser/actions.lua` record commands
  as space-joined strings** — ambiguous for keys containing spaces. Display
  + copy concern only (never re-executed by the plugin; `yank` pipelines
  quote the pattern). A proper fix is a quoted-render helper across all
  `record()`/`history.push` call sites — noted as a smell below.
- **`session_conn.cleanup_buf` stops ANY session with an empty `bufs` map** —
  sessions started via `execute(..., nil, ...)` (all current callers) never
  register a buffer, so closing the browser stops every pooled session. This
  matches the documented "sessions survive close; cleanup_buf stops empty
  ones" intent but is coarser than per-owner refcounting; fine until
  multi-window sessions matter.

## Smells identified + suggested remediation

- **`tree.flatten_tree` mutates the caller's children arrays** (fold_walk
  result written back into `nodes[i]`, which aliases real `node.children`):
  the model graph and display graph alias. Works because folds are recomputed
  every render and scans rebuild lazily, but it is fragile. Remediation: fold
  on a copied display list, or track fold state as a node field.
- **Command history strings are unquoted concatenations** (above): add a
  single `util.render_command(args)` (quote args containing whitespace) and
  use it in `record`/`history.push`/`exec` call sites.
- **`exec_run.run_sync` is blocking** and now used by `browser/value.load_full`
  (64 MiB cap) — a large value freezes the UI on `F`. Remediation: move to
  `run_async` with a one-shot callback when convenient.
- **`doc.lua` creates an augroup per doc float** (`PosteRedisDocWin_<win>`);
  the autocmd dies with the window but augroups accumulate. Remediation: one
  shared group, drop the tracker in the callback.
- **`session_conn.execute` registers no buffer owner** (see above) —
  per-caller refcounting would make `cleanup_buf` precise.
- **Pre-existing luacheck warnings** (7 in `lua/`, 31 in `tests/`): mostly
  shadowing in specs; safe mechanical renames whenever someone is in there.
