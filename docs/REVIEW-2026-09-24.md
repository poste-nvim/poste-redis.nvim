## Bugs fixed

41. **A continuation that split a WORD deleted the wrong keys**
    (`parser.lua`, `fc6e575`). `extract_entries` joined per-physical-line
    token LISTS, so `DEL a-\` + `b` arrived at the binary as
    `{"DEL","a-","b"}`: two unrelated keys where redis-cli — which lexes the
    whole logical line — sends one key `a-b`. A silent wrong-target write in
    the worst direction the family has; `GET very-\` + `long-\` + `key`
    mis-read the same way. `tokenize_line` now reports whether the chunk ends
    inside an open bare word, and the join merges bare+bare across the
    boundary (`a-` + `b` → `a-b`). A chunk ending in an open QUOTED token
    stays split — the quote never closed, and merging would guess where the
    string ends (that shape is pinned as a known split, see "Recorded").

42. **`\xHH` byte escapes were not decoded** (`parser.lua`, `fc6e575`).
    redis-cli's `sdssplitargs` accepts `\x41` in double quotes; the parser
    kept the five literal characters `backslash x 4 1`. `SET k "\x41"`
    therefore wrote a key named `\x41`, and `GET "\xff"` could never reach a
    binary-safe key — the one place the file format can carry non-UTF-8
    bytes at all. Decoding follows the same rules as `sdssplitargs`: two hex
    digits required, malformed (`\xzz`) or truncated (`\x` at end) escapes
    stay verbatim, and the decode is one pass, so `\\x41` (escaped
    backslash + `x41`) still decodes to backslash + `x41`, never `A`. A
    decoded NUL is wire-safe (JSON `\u0000`) but would be coerced to a
    newline inside a buffer line, so `util.escape_for_line` now maps it to
    the visible `\0`.

43. **A set-member rename could silently delete a member**
    (`browser/grid_edit.lua`, `0497dab`). The `set` branch was the only
    rename without a name-free probe: `SREM` removed the source member, then
    `SADD` found the target already present and added nothing — one "edit"
    cost one member, no warning. Hash (HEXISTS) and zset (ZSCORE) have run
    this probe since they shipped; set now probes `SISMEMBER` first and
    refuses with the same "edit that row instead" message.

44. **`result_height_ratio` and `history_max` did nothing; `debug` promised
    a command that does not exist** (`buffer.lua`, `config.lua`, `init.lua`,
    `3eb51f7`). `show_panel` read the `constants.RESULT_HEIGHT_RATIO`
    constant, so the documented config key was dead. `history.set_max_history`
    existed precisely to take `config.history_max`, but only the constant
    was ever fed. And the `debug` key advertised `:PosteRedisDiag` — a
    command no code defines (diagnostics live in `:checkhealth`). The first
    two are wired through setup(); the third is deleted with its doc row.

45. **Yanked redis-cli pipelines broke on quotes and spaces**
    (`browser/actions.lua`, `f1b3493`). The yank forms are paste-ready shell
    lines, but only for clean names: a prefix containing `'` broke the
    `--scan --pattern '…'` quoting mid-pipeline, the batch `DEL` joined key
    names with spaces (a key `a b` pasted back as two keys), and the
    `set_ttl_nodes` per-key `redis-cli EXPIRE '…'` lines had the same hole.
    Prefixes are now POSIX single-quote-escaped (`'\''`); key lists go
    through `util.render_command`, which already owned the quoting rules the
    history line uses.

46. **`EXPIRE key 0` — Redis' delete-now — had no confirm gate**
    (`browser/actions.lua`, `24ae0e3`, closing the first "Recorded" item
    below). The `t` prompt documented `-1 = PERSIST` but not what `0` does,
    and `0` was the one destructive browser action with no gate: a
    fat-fingered 0 destroyed the key, leaving only a history entry behind.
    The prompt now says `0 = delete now`, and a `0` answer runs the same
    explicit confirm `DEL` uses; the declined path dispatches nothing.

## Recorded, not changed

- **`delete_prefix_keys` detaches the group node even when the DEL batch
  partially failed.** The notify and the history entry both say how many
  survived, but the row disappears and the surviving keys are invisible
  until a manual refresh. `delete_nodes` keeps nodes it could not scan for
  exactly this reason; the partial-DEL case detached anyway. Fixing it
  means re-scanning the prefix from the failure path — a bigger change
  than this pass wanted.
- **A quoted token that spans a continuation stays split** (pinned in
  `parser_spec`): `SET k "va\`+`lue"` reaches the server as two args,
  quotes included. redis-cli keeps lexing inside the quote across the
  newline; that needs a real streaming lexer, not a per-line tokenizer.
  The split is visible in the tokens and in `raw`, and the word-merge fix
  (41) deliberately does not touch it.
- **The context cache's incremental boundary still parses a continuation
  fragment as a standalone line** (`context.lua`) — pre-existing, already
  documented there; fragments are never USE/SELECT, so the worst case is a
  stale statusline context until the next edit, not a wrong execution.
- **`toml.lua` rejects a quoted key that contains a dot**
  (`"my.key" = 1` errors as a dotted key). TOML-legal, but no
  connections.toml in the family uses quoted dotted keys, and the parser is
  vendored from poste-db — a fix belongs there first, then a re-copy.
