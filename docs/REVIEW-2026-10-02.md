## Fix (with tests)

- **`statusline.get_ctx_color` type-gates `color`/`link`/`bg`**
  (`statusline.lua`). The TOML parser turns `color = [1]` into a real
  table; the field used to be concatenated into the cache fingerprint
  (`..` on a table raises) and `:sub`-ed for the `#`-check — both
  inside a function every statusline redraw and cursor move runs, the
  exact one-typo-takes-the-UI-down shape the round-24 sweep closed for
  `host`/`url` but these three sibling fields kept. A non-string field
  now counts as absent, so the entry simply renders uncolored.

## Probed, held

- **`grid_edit` paging and sorting** — `cursor_cell`'s
  `(page-1)*page_size + row` mapping matches the 1-based cursor
  convention every other consumer uses (`preview`, `sort`, `yank`);
  `sort.apply` carries each row's index cell along, so a list edit
  after `s` still addresses the true server-side index.
- **`verified_list_write`'s LINDEX probe fails safe in both hazard
  directions**: a shifted list mismatches and refuses the write; an
  offset-anchored result (see below) refuses every write — annoying,
  never wrong-target.
- **`exec_run.group_by_connection`** on bare USE, failed resolves, and
  a trailing USE with no commands: error groups and empty-batch skips
  behave as documented (the dispatch chain cannot strand).
- **`buffer/export` transforms** take `grid.to_copy` (= `util.
  to_clipboard`), which always returns a string — no table cell can
  reach `csv_field`'s `:find`.
- **`util.render_command` vs the Rust `display_command`**: for C1
  controls (U+0080–U+009F) the Lua side passes the bytes through
  verbatim (`%c` is byte-wise and never matches either UTF-8 byte)
  while the fixed Rust side now escapes each byte — different display,
  same round-trip through the Lua tokenizer's `unquote`. Both sides
  recover the original token; the divergence is cosmetic only.

## Read, not changed (recorded on purpose)

- **Editing a list whose result does not start at the head is always
  refused with a misleading message.** For `LRANGE key 5 10` or
  `LINDEX key n`, the grid's index column is result-relative, so the
  LINDEX verification in `verified_list_write` mismatches every time
  and says "List changed since render — press r to refresh" — advice
  that cannot help. Fail-safe, but a real fix wants the query's anchor
  range recorded in the tab meta so the edit can be refused with the
  true reason (or translated). Feature-sized; left open.
- **`add_row` on a stream tab falls into the SET branch.** The server
  answers WRONGTYPE and the panel shows the failure, so nothing is
  corrupted — but the prompt reads "Value to SET on …" for a key the
  user knows is a stream. Cosmetic; a stream branch (XADD form) is the
  real fix if stream editing ever becomes a goal.
- **A rescue retry in the Rust redis session can re-execute a
  non-idempotent command** when the first attempt reached the server
  but its reply was lost (`INCR` counts twice). Recorded on the Rust
  side this round (REVIEW-2026-10-02.md); noted here because the Lua
  session rides the same transport.
