## Fixes (each with tests)

- **A token-less continuation line reset the open-word flag**
  (`parser.extract_entries`). The flag bookkeeping recomputed `open_bare`
  from the current chunk's tokens — of which an empty continuation
  (`\` alone on a line) has none — so a word opened on an earlier chunk
  flipped to closed and the next chunk arrived as a separate token:

  ```
  DEL a-\
  \
  b      ->  DEL a- b   (deletes the two unrelated keys a- and b)
  ```

  That is the exact silent wrong-target write the word re-join exists to
  prevent, resurfacing through a rare spelling. A token-less continuation
  now preserves the flag; the flush on a non-continuation line still
  resets it.

- **`toml.lua` re-vendored from poste-db@7ba2df1**, per the vendored
  header's re-copy contract, picking up two fail-closed fixes: `[a] [b]`
  errors instead of silently swallowing the second section, and
  `"""…"""` errors instead of unquoting into the garbage value `""x""`.
  Mirror specs added to `tests/redis/toml_spec.lua`.

## Verified, left alone

- **`render_command` → `command_tokens` round-trip holds** for every
  hostile token probed: spaces, embedded quotes, backslashes, newlines,
  tabs, literal `\x41` text, a leading quote, the empty token, raw
  control bytes and CJK. The escapes mirror the Rust `display_command`.
- **One wedge in the mirror**: a token containing a C1 control character
  (U+0085–U+009F) escapes as `\x85` on the Rust side (`c as u32`, two
  UTF-8 bytes collapsed to one byte) and decodes to a *different* string
  on re-parse. Rust `char::is_control` reaches U+009F; the practical
  route to such a key is writing `\u{85}` in a script — not reachable
  from a `.redis` buffer, whose escape set is byte-level. Recorded, not
  actioned.
- **The danger blacklist is exactly FLUSHALL/FLUSHDB/SHUTDOWN/CONFIG**,
  which is what the README promises. `EVAL` (a script can `FLUSHALL`),
  `DEBUG`, and `REPLICAOF` are the debatable additions; each would add
  friction to legitimate work, so the list stays as documented.
- **`key_arg`'s NOT_KEY_HEADS** checked against Redis 7 command shapes:
  the key-first commands (SORT, BLPOP, HSCAN, XRANGE, COPY, LPOS, …) are
  correctly absent; the subcommand-first and count-first ones are listed.
- **`build_url_from_fields`** rejects non-integral and out-of-range
  ports without echoing the value (it may be a resolved secret), and
  `db` has no upper bound by design (server-side setting).
- **The empty continuation chunk between quoted fragments** stays split,
  unchanged from the documented quoted-chunk contract.
