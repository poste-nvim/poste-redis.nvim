## Fixes (each with tests)

- **A missing poste binary reported its failure twice.** `cli.run_async`
  synthesizes a synchronous `on_exit(-1)` when no binary was found, and
  `exec_run.run_async`'s exit handler ran the whole no-summary path on it —
  one `on_error` plus one `on_done` unwind — before the failed-start branch
  added a second `on_error`/`on_done` pair. One missing binary meant two
  error toasts and, from the runner, two history pushes / panel renders per
  USE group. The synthesized exit now stays swallowed (identifiable by
  arriving before any job registered in `active`), the failed-start branch
  is the single delivery, and the start-failure check covers a `0` job id
  (`< 0` before), which previously registered as started and could have
  stuck `busy`. Same defect family as poste-db's `async.run` fix this round.

- **The connection/context pickers reshuffled between opens.**
  `list_connections_sync` built its list from `pairs()` over the parsed
  toml, whose order flips as `connections.toml` is edited.
  `redis_connection_names` already sorted for completion; the sort now lives
  at the source so both pickers and every other consumer inherit it — the
  same fix poste-db applied to its picker at round 42.

- **A UTF-8 BOM at the top of a `.redis` file folded into the first
  token.** Windows editors and PowerShell's `Out-File` write a BOM by
  default; with `'bomb'` off Neovim keeps U+FEFF as line 1's first
  character, so the first command reached the server as `<feff>SET` and was
  rejected as an unknown command while the buffer shows a plain `SET`.
  `extract_entries` (the single entry point behind buffer parsing) strips
  it. CRLF line endings were probed too and already parse correctly.

## Verified clean rather than assumed

- `history.lua`'s sidebar build: newest-first spans line up with the
  newest-last storage (`history[#history - (offset - 1)]`), the empty-history
  placeholder keeps `spans` empty, and the pad/truncate budgets add back up
  to the float width for a full-width command.
- `result/grid.lua`: `render_page` clamps `page` into range; byte-column
  arithmetic (`#SEP` = 3, 0-based ext ranges) is consistent between
  `row_line`'s maps and the highlight consumers.
- `exec_run`'s injected-SELECT bookkeeping: `payload_idx` counts every
  payload result (including the swallowed one), so `select_targets` rebinding
  and result renumbering stay entry-aligned when `opts.db` is set.
