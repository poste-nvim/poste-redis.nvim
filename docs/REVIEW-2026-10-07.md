## Bugs fixed

1. **chansend throws on a dead channel — both write paths were unguarded**
   (`cli.lua`, `session_conn.lua`). Measured, not assumed: `vim.fn.chansend`
   on an invalid channel id raises `E900`, and on a channel whose stdin
   stream already closed it raises "Can't send data to closed stream" —
   the `sent <= 0` checks were dead code for every real failure, because
   the throw happens first. A process dying between `execute`'s alive
   check and the write therefore skipped the pending cleanup and the
   caller's on_error: a scan loop left its nodes loading forever, and the
   stdin write inside `cli.run_async` propagated past every callback and
   left `exec_run`'s busy flag stuck (red line #4). Both writes are now
   pcall'd and funnel into the existing send-failure handling, the way the
   SELECT path already hardened itself. Pinned by two dead-channel specs
   (command path and SELECT path) plus a `cli.run_async` throw spec.

2. **Unbalanced inline brackets stored garbage silently** (`toml.lua`).
   `[1]2]` ends in `]` so the unclosed-array check passes; `split_top`
   consumed every closer into the buffer while `depth` drained below zero
   and the tail survived as one string — the config stored `ips = "1]2"`
   with no error anywhere, the exact silent-typo class this parser
   otherwise refuses (double commas, missing container halves). An
   unbalanced container now fails closed. Pinned by `[1]2]`, `{ a = [1 }`
   and `[[1, 2]` specs. Mirrored into poste-db's vendored copy the same
   commit.

3. **`truncate_display` returned one cell more than asked at width 0**
   (`util.lua`). The ellipsis alone is one cell; the old loop returned it
   even when `max_width` was 0 (or negative), so the "fit inside
   max_width" contract broke exactly at the widths that cannot afford the
   reservation. Widths below one cell now truncate to the empty string.

## Vendored-copy parity (acted on this round)

The round-29 smell — vendor pins go stale by design — produced its
predicted drift today: poste-db's `toml.lua`, `cli.lua` and
`session_conn.lua` carried the same three holes. Both sides are fixed in
lockstep now (poste-db commits `286371b`, `a151230`), and the tail-diff
check stays the cheap mechanical guard.

## Probed, held (recorded on purpose)

- `parser.extract_entries` on a continuation backslash at EOF, a backslash
  inside quotes at EOL, an unterminated quote, a lone quote token, a NUL
  byte, and a reversed visual range: all behave (entries parse, ranges
  order); no change.
- `session_conn.M.stop` fails pending requests only via the eventual
  on_exit — a session wedged hard enough to ignore stdin EOF would hang
  its pending forever outside watchdog scope (it left the pool in stop).
  Not reachable today: the Rust session loop exits on stdin EOF regardless
  of TCP state. Held; revisit if the session loop ever blocks on write.
- The stall watchdog's timer runs for the editor's lifetime (never
  stopped, `stop_all` leaves it armed): a no-op while the plugin is
  loaded, and there is no teardown path to hang it off. Held.
- `format.status_summary` renders a negative `latency_ms` verbatim; the
  binary never produces one. Held as a display-only nicety.

## Cross-repo note (belongs to poste.nvim, recorded here because both
## transports meet it)

The Rust `redis-session` rescue retries a command after a reconnect when
the first attempt timed out — a command that completed server-side but
answered slower than the 30-second bound runs twice (a double INCR). The

rescue exists to prevent; recorded as a deliberate trade-off, not a bug
