## Fixes (each with tests)

- **The live e2e action tests only worked against a `/0` URL.**
  `browser_spec`'s live block built its key nodes with
  `meta.db = 0` while the bare session seed/verify calls ran on the
  URL's default db. On CI's `redis://…:16479/0` the two coincide, so
  the suite stayed green; against `/9` the seed landed in db 9 while
  `rename_key`'s `{db = meta.db = 0}` SELECTed db 0 — RENAME answered
  "no such key", the action notified the error (its `on_error` does not
  fire `ctx.render`, so the test's `done` flag just timed out), and the
  EXISTS assertion failed on a key that had never existed in the db
  being verified. `delete_key` carried the same mismatch and passed by
  accident: its verify ran on the session the DEL had just steered to
  db 0, so "gone" was true of an empty database, not the seeded one.
  Both tests now derive `db_num` from the URL and pin every call and
  the node to it; behavior on CI's `/0` is unchanged. Found by running
  the suite against a non-zero-db URL — the CI harness cannot see this
  class.

- **The yank cell preview split CJK glyphs in `:messages`.**
  `yank.cell`'s notify cut the preview at raw byte 40 — inside a 3-byte
  glyph for any CJK value, printing U+FFFD. Now
  `util.truncate_display` (display-width cut, no character split,
  ellipsis appended). Third sighting of the byte-cut family this round:
  poste-db fixed two summary dialogs the same day.

- **`buffer/sort.lua` got its first spec** (the last stateful piece of
  the result panel without one): numeric-string comparison (redis
  replies are strings — scores like `"99"` must order numerically), nil
  cells from short rows comparing without raising, the stable tiebreak,
  the desc→asc→none cycle including a fresh column restarting at desc,
  the focused record following its row across the re-order, and the
  header icon's byte range. The icon range is a positional pair
  (`icon_hl[1]/[2]` in `header.apply_sort_hl`); both docstrings claimed
  field names — corrected.

## Verified clean rather than assumed

- **`browser/scan.lua`'s cursor loop** terminates on the binary's SCAN
  cursor because that cursor is a JSON *string* (pinned Rust-side by
  `scan_surfaces_cursor_as_list`); `spine_fold`'s `sub(#pfx + 2)` rest
  extraction holds for every bucketing invariant the builders maintain,
  including trailing-colon keys (redis glob `*` matches empty, so
  `MATCH pfx:abc:*` still finds the key `pfx:abc:`).
- **`parser.extract_entries`** held up against the remaining hostile
  shapes: `#` glued inside words (`user#1`), quoted `#`/`--` tokens,
  escaped-quote scanning with doubled backslashes, `""` empty-string
  tokens, continuations ending the buffer. The one divergence found —
  `"a\"` (unclosed quote with a trailing escape) decodes to `a\` where
  redis-cli would call the token unterminated — is malformed input whose
  raw form still round-trips visibly; recorded, not changed.
- **`buffer/preview` / `buffer/view`**: page/cursor arithmetic bounds
  check before every grid index; `format.preview_json` is a pcall'd
  thin wrapper; the winbar's `format_command` splits keys on spaces by
  design (typed form kept).
