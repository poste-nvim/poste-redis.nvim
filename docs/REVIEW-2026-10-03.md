## Fixes (each with tests)

- **The TOML parser re-syncs from poste-db 2216036** (`toml.lua`).
  Body copied verbatim: a quoted key carrying its own `=` (`"a=b" = 1`,
  legal TOML) used to be cut at the quote-inner `=` and stored the
  mangled halves with no error, an inline-table key's swallowed parse
  error stored the entry under `tostring(nil)`, and `["x"] # comment`
  died as an invalid header. Six regression specs ride along.
- **`NOT_KEY_HEADS` gains the numkeys family's missing siblings and
  BITOP** (`parser.lua`, 6f3f330). `SINTERCARD` was listed but
  `ZUNION` / `ZINTER` / `ZDIFF` / `ZINTERCARD` — the same numkeys-first
  shape — were not, so `ZUNION 2 a b` revealed the key `"2"` to the gd
  tree jump and sent a `TTL 2` probe to the server from the winbar.
  `BITOP`'s second token is the set operation (AND/OR/XOR/NOT), not a
  key; same false-positive class.
- **Single-quoted tokens decode the one escape redis-cli processes**
  (`parser.lua`). `'a\'b'` kept the backslash and targeted the key
  `a\'b` where the identical redis-cli command names `a'b` — the
  wrong-target write class the de-quoting exists to prevent.
  Everything else in a single-quoted token stays verbatim (the gsub is
  paren-truncated so the match count cannot leak out of `unquote`).
- **`ai/system_prompt.build` type-gates the chat scope's connection**
  (3626b5d). The scope map comes from poste-ai and is hand-buildable; a
  number or table where the connection belongs reached the string
  concat and killed the whole prompt build inside the chat request.
  Non-string now counts as absent (falls through to the context
  connection) — the same gate the poste-db sibling put on the identical
  field. String readings unchanged; an explicitly empty scope name
  still suppresses the line. First specs for the module.
- **`cli.run_async` survives `jobstart` raising E475** (5719483).
  `jobstart` raises `Vim:E475` on a bad argv[0] (probed) instead of
  returning an error; the binary can vanish between the lookup and the
  start (a reinstall, a stale `g:poste_binary`). The uncaught throw
  skipped every on_error/on_exit and left the caller's spinner running;
  it now answers with the same synthesized `on_exit(-1)` + nil the
  binary-missing path uses. First spec for the module.
- **`install_binary` reports a missing curl instead of crashing plugin
  load** (5719483). `vim.fn.system` raises the same E475, and both curl
  calls sit on the setup() path via `ensure()`: a box without curl
  crashed plugin LOAD where health's warning promises "auto-download
  will fail". The download reports "curl is not available on PATH"; the
  checksum fetch skips verification, same as an unavailable checksum
  file.

## Probed, held (recorded on purpose)

- **`highlights.link_if_empty` defines the builtin treesitter capture
  groups** (`@comment`, `@string`, `@number`, …) globally when the
  colorscheme has not. Aggressive but deliberate (the header documents
  the ColorScheme re-run), and the `tbl_isempty` gate is the correct
  missing-group test the poste-db sibling had to fix in its round 49 —
  this copy already reads `nvim_get_hl` correctly.
- **`install_binary.verify_checksum` skips verification on a 200-empty

  anyone able to blank the checksum can also replace the archive.
- **`parser` quoted-header names with escaped quotes** (`["a\"b"]`) —
  `find(q, 3, true)` finds the first quote, mid-escape. Exotic for a
  connection/file header; held.

  sibling `mq_session.rs` (read via poste.nvim) — no issues; the
