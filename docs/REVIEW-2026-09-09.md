## Hardening

- **`browser/actions.delete_nodes` ran every batch DEL with the first
  node's db** (815e1ab). Each selected node's SCAN correctly paces its own
  prefix under `job.node.meta.db`, but the delete loop passed
  `nodes[1].meta.db` for the whole batch — a key collected by a db-2 SCAN
  would be deleted with db-1 selected (hitting an unrelated key, or
  nothing). Not reachable through the UI today (multi-select is restricted
  to nodes under the current db, `toggle_multi_select` docstring says so),
  so this is hardening rather than a live fix: `flat` entries now carry the
  owning node's db. Pinned by a two-db spec — lifting the single-db
  restriction can no longer silently turn this into a cross-db delete.

## Observations

- **`bufnr(pattern)` lookups are prefix-hazardous**: `history.lua:280` and
  `buffer.lua:460` look up "stale" buffers by `vim.fn.bufnr("poste://…")`
  before renaming, and `poste-es` has the same shape. All current buffer
  names are prefix-disjoint so nothing misfires, but the poste-mail round
  today fixed a real clobber caused by exactly this pattern (a list buffer
  name being a prefix of a detail buffer name). If another buffer name
  ever gains one of these prefixes the stale-delete would delete the wrong
  buffer; an exact-name lookup (see poste-mail `ui/common.find_named`)
  removes the hazard.
- Yank/preview are data-faithful: `buffer/yank.lua` and `buffer/preview.lua`
  read `tab.grid.rows` (all pages, raw values via `to_copy`) rather than
  the rendered view — unlike poste-es's body yank, no truncation issue.
  One small wart: `add_page` appends the "loaded N / total M" footer to
  text-page lines, so `yank current` on a text tab copies the footer line
  with the value. Cosmetic; noting it since the poste-es round changed
  yank semantics in the family and the asymmetry should be a decision.
- History snapshots still hold whole panel text per run (carried from
  09-08, unchanged).
