## Fixes (with tests)

- **`buffer/search.next/prev` crashed on a tab that never searched**
  (`e02a3da`). Both read `#tab.search_matches` directly; a table tab
  whose search fields were never initialized died with "attempt to get
  length of field 'search_matches' (a nil value)". The `render_tabs`
  path always initializes `search_matches = {}`, so no shipped flow
  reaches it — but the module now tolerates absence the same way
  `view.apply_search_highlights` (its own sibling) does. The new spec is
  the regression test.
