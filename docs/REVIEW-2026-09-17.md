## Bugs fixed

1. **The vendored toml.lua had silently drifted three fixes behind its
   source** (`lua/poste-redis/toml.lua`, pinned to poste-db@b7aefc6 while
   poste-db moved to 94fccf2). Missing: literal strings (`'…'`) must not
   skip 2 chars after a backslash (`'a\'` ate the closing quote and
   misparsed the rest of the line); UTF-8 BOM stripping (a BOM-prefixed
   connections.toml failed as "Invalid key=value line"); unclosed-string
   errors no longer echo the value (secrets land in logs/notifications).
   Re-copied from poste-db@94fccf2 with the vendored header bumped; four
   spec cases pin each behavior. This is exactly the drift class the
   vendored-file header warns about — worth greping every vendored file
   against its live source on future passes.

2. **`browser/scan.lua` captured `browser_split_nest` at module load** —
   a value set by a later `setup()` was silently ignored (the browser
   modules are required lazily and can load before the user opts merge).
   `split_nest()` now reads the config per call; a spec pins the call-time
   behavior by overriding the config mid-test.

3. **The browser `g?` help still described search as sub-path matching** —
   async.search has been substring matching (`*query*`, glob-escaped) since
   the fuzzy-search change. Help text now matches the code, and
   `ui.centered_float` splits embedded newlines instead of failing the
   whole float with E5108 (found while editing that help text: a `"\n"`
   inside a help line took the float down).

## Recorded, not changed (with rationale)

- **session_conn STALL_LIMIT (10 s) is shorter than the binary's own
  COMMAND_TIMEOUT (30 s)** — a legitimately slow command (>10 s, e.g. a
  huge DEL) gets its request failed Lua-side and the session restarted
  while the Rust side would still have delivered. Both sides recover;
  the Lua watchdog exists for the stall case the binary cannot see
  (dead TCP where the driver never resolves). Raising STALL_LIMIT above
  the binary's worst-case rescue path (30+10+30 s) trades stall
  responsiveness for correctness on slow commands — revisit if a real
  workload trips it.
- **`session_conn.stop()` never `jobstop`s a hung session** — closes
  stdin and relies on EOF (same known gap as poste-db's stop); after
  stop() the session is out of the pool, so the watchdog no longer sees
  it. A wedged process lingers until nvim exit.
- **`scan_session_opts` max_items (= max scan counts + 1000) can still
  truncate a SCAN page**: SCAN's COUNT is a hint, Redis may return more
  than COUNT keys in one page, and the extra keys are dropped silently
  (cursor keeps advancing). Bounded by the same DISPLAY-cap stop that
  halts paging on truncated trees; a `max(header, body)+1000` reply of
  >6000 keys in ONE page is the only loss case.
- **`fetch_dbs` probes a fixed 16 databases** (constants.REDIS_DB_COUNT) —
  a server configured with `databases 32` hides dbs 16–31 in the picker
  (matching `pick_db`'s static list). Surfacing CONFIG GET databases is
  future work.
- **`util.redact_url` keeps a colon-less userinfo verbatim**
  (`redis://token@host` is not redacted) while `host_label` redacts any
  userinfo. Deliberate per the tests (username ≠ credential), but the
  two helpers disagree on what "userinfo" means; a token-as-userinfo URL
  would leak into logs through redact_url paths.
- **`exec_run.dispatch_group`'s fire-time guards compare exec_seq with
  itself** (guarded(exec_seq, ...) called immediately) — they are no-ops
  by construction, documented as such; the seq checks *between* dispatch
  steps are what actually protect the chain.
